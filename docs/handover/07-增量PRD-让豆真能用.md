## 2. 用户原始诉求与三步范围

### 2.1 用户原始语句（逐字）

> 「1→2→3 修到真能用，团队所有人一起干活」

承接 `06` 实施后暴露的问题：网关已加固，但**存量桌面客户端**在鉴权前编译、不带令牌，实测 401 / 429 / 黑屏 / 状态误导（§3）。用户要求按三步把「能打开窗口」修到「真能用」。

### 2.2 三步范围（用户给定 → 本文需求映射）

| 步 | 用户措辞 | 本轮实质工作 | 对应需求 | 对应判据 |
|---|---|---|---|---|
| **1** | 起 SSH 靶机 | 本机 `127.0.0.1:22` CLOSED、`wsl.exe` 被黑名单拦截且禁止绕过、OpenSSH 未装 → **本机无现成靶机**；本轮做「可配置靶机入口 + 优雅离线态」，**不绕过安全策略、不擅自安装系统服务** | FIX-08、FIX-09、FIX-10 | AC-05（可用时）/ AC-06（不可用时） |
| **2** | 补令牌并重编 | 令牌桥接（Rust 侧读 `token.txt` + 前端统一注入）+ 占位符本地替换 + 防爆破兼容 + `npm run build` 重编内嵌 `dist` 的 exe | FIX-01~05、FIX-07、FIX-11 | AC-01/03/04/07/08/10 |
| **3** | 收编源码 | 把 `E:/dou-app/` 真实客户端收编进仓库 `app/`，替换 greet 模板，消除双份源码 | FIX-06 | AC-09 |

### 2.3 因果链（本轮为什么这样修）

1. `06` 落地 W-15 统一鉴权 + 防爆破：无/错令牌 → 401，连续失败 → 429（带 `Retry-After`），**带主令牌全部 200**。【06 报告 §3 / 用户实测】
2. 存量 `E:/dou-app/app.exe` 是**鉴权前**编译的，所有 REST **不带 Bearer** → 命中 401，页面初始化并发重试 → 命中 429。【实测结论】
3. `06` 为消除明文回吐，把 `/onboard/config` 片段的 Authorization 改为 `Bearer ${DOU_TOKEN}` 占位符 → 旧「复制片段 / 一键代写」拿到的是**不可用占位符**。【实测结论 + 06 报告 §4】
4. 本机无 SSH 靶机 → 终端黑屏 `os error 10061`、文件树空白、编辑器「未打开文件」。【实测结论 `dou-window.png`】
5. 状态灯「网关 在线」与接入向导「网关离线」并存 → **连通性判定分叉、UI 误导**。【实测结论 `dou-onboard.png`】
6. `app.exe` 内嵌 `dist`（无到 1420 的 TCP 连接），改前端源码**必须** `npm run build` + 重编 Tauri exe 才生效。【实测结论】
7. 两套源码（仓库模板 / 仓库外真实端）并存 → 改错文件、产物与源码不一致。【实测结论】

> 结论：**网关不动、客户端接回去**。修好令牌桥接与离线态 = 消除 401/429/白屏/黑屏/状态矛盾；收编 + 重编 = 让修复真正落到可构建的唯一真源。
