## 2. P0 —— 首屏 30 秒去留问题（陌生人第一眼）

### R1 首屏「新建连接」表单

- **问题**：默认目标是内测 WSL 靶机 `127.0.0.1:22 / dou`，推广后 100% 用户首屏是离线态；「网关在线」与「靶机未连接」同屏矛盾。App.vue `onMounted` 自动 `newTab()` 连默认值，是开发者行为不是产品行为。
- **整改**：
  1. `useSsh.ts` 的 `SSH_HOST/SSH_PORT/SSH_USER` 常量降级为**表单初始空值**（不再钉死任何机器）；
  2. 无已解锁档案时，首屏终端区呈现「新建连接」卡片：host / port(22) / user / 认证方式（密钥|密码）/ 密码框（密码模式），一次提交即连（密钥模式调 `open_pty`，密码模式同表单内输密码）；
  3. 已有档案时优先展示档案列表（衔接 R8）；
  4. 去掉自动 `newTab()` 连 127.0.0.1 的启动行为。
- **验收**：① 清空 `app_data_dir` 后启动：首屏是连接表单，界面无 127.0.0.1/「靶机」字样残留（截图）；② 表单提交后成功进终端 / 失败出引导文案；③ vue-tsc + vitest + verify.sh 全过。
- **范围**：dou-app `core/useSsh.ts`、`core/useTerminal.ts`、`views/App.vue`、`components/TerminalPanel.vue`（或新 `ConnectForm.vue`）。

### R2 侧栏信息架构重组

- **问题**：侧栏 13 项中「实验详情/审批/传输队列/策略配置/审计中心/凭据与作用域/主机密钥/接入向导」多为内部工单概念，新用户无法建立心智模型；「实验详情」尤其突兀。
- **整改**：**不删功能，只重排**。默认侧栏收敛为 ≤7 项自明入口：终端 / 文件 / 连接管理 / 设置 / 帮助（新增，指向文档入口占位）；「实验详情、审批、传输队列、策略配置、审计中心、凭据与作用域、主机密钥、接入向导」收进「高级」可折叠分组；每项补 tooltip 一句话。
- **验收**：① 默认展开项 ≤7 且每项 tooltip 自明（截图）；② 高级分组内原功能全部可达（侧栏逐项点击过一遍）；③ 分层检查 0 违规、前端单测 16/16。
- **范围**：dou-app `views/App.vue`（侧栏）、`core/useNav`、受影响页面组件仅改标题文案不改逻辑。

### R3 状态区与错误文案人话化

- **问题**：①「网关 在线」绿徽章与「靶机未连接」灰字同区混排，负向状态无颜色权重、无动作指引；② 文案大量「靶机」「内测」术语（`sshOfflineReason`、OfflineState、状态说明）；③ 用户不知道下一步点哪里。
- **整改**：
  1. 状态区拆两行：`连接网关：在线/离线`（绿/红点）+ `远程主机：未配置 → [添加主机]`（链接跳新建连接/连接管理，走 `useNav`）；
  2. `useSsh.ts sshOfflineReason` 全量重写：去「靶机」，每条 = 原因 + 动作（如「目标主机没有响应：请检查地址和端口，或在连接管理中修改」）；
  3. OfflineState 文案同步（terminal/files 两变体）；审计轨迹 (`audit`) 文案同步。
- **验收**：① 断网/拒绝/超时/认证失败四场景各截一张离线态，文案无「靶机」字样且含动作；② grep 全 `src/` 无「靶机」残留（排除历史注释酌情）；③ verify.sh 全过。
- **范围**：dou-app `core/useSsh.ts`、`components/OfflineState.vue`、状态区组件、个别页面标题。

## 3. P1 —— 日常使用露馅点（用过三次内决定口碑）

### R4 本地 Shell 升级 ConPTY 真终端

- **问题**：`open_local_pty` 是 stdin/stdout 管道桥，非真 PTY：`vim/htop` 画面乱、Ctrl+C 信号不完整、resize 不同步。MobaXterm 本地终端用 ConPTY。
- **整改**：Rust 侧 `pty.rs` 本地模式改用 Windows ConPTY（`windows` crate `CreatePseudoConsole` + 管道转发），保留既有 `pty_data/pty_write` 事件协议不变；resize 时 `ResizePseudoConsole` 同步 xterm cols/rows（新增 `pty_resize` 命令或复用既有通道）。
- **验收**：① 本地 Shell 内 `vim` 进入/编辑/退出画面不乱（截图）；② 拉伸窗口后 `mode con` 与窗口行宽一致；③ `cargo test --lib` 通过；④ 失败兜底：ConPTY 不可用（Win8 等）回退管道模式并在终端横幅标注「基础模式」。
- **范围**：dou-app `src-tauri/src/pty.rs`、`Cargo.toml`（+windows crate）、前端 xterm onData→resize 联动。
- **备注**：Rust 大件，独立分支小步提交；SSH 远端会话不受影响（russh 自带 PTY 请求）。

### R5 密码认证动线收进连接表单

- **问题**：密码认证三步分散（工具条选认证方式 → 工具条输密码 → 点 +），用户不知道作用范围；工具条密码框是 R1 之前的历史方案。
- **整改**：随 R1 落地——工具条的认证下拉与密码输入框移除，认证方式与密码只在「新建连接」表单内出现；`authMode/sshPassword` 状态迁入表单组件。
- **验收**：① 工具条无密码框（截图）；② 密码模式连接 ≤3 步（填表→提交→终端）；③ R1 验收连带通过。
- **依赖**：R1。

### R6 终端工具条重排与降噪

- **问题**：单行塞 7 个交互元素；「检索会话」占黄金位、「广播到勾选」单会话时是纯噪声、「导出」语义不明、两个「本地 Shell」视觉误读。
- **整改**：「+ 新建会话」变主按钮（图标+tooltip）；「本地 Shell」并入「+」旁的次按钮；「检索会话」会话 ≥5 个时才出现；「广播到勾选」仅在勾选 ≥1 时出现并改名「同时输入到所选会话」；「导出」移入溢出菜单（⋯）。
- **验收**：① 单会话新用户视角工具条元素 ≤4（截图）；② 多会话时广播/检索回归可用（UIA 点击复验）；③ verify.sh + 前端单测全过。
- **范围**：dou-app `components/TerminalPanel.vue` 模板与少量 `useTerminal` 派生状态。

### R7 监控条主机边界显性说明

- **问题**：monitor.rs 只支持 Linux `/proc`；连 Windows 主机时监控条静默隐藏，用户以为功能坏了。
- **整改**：`host_stats` 失败时区分原因——若远端非 Linux（exec `uname -s` 探测），前端显示一行「监控暂不支持该主机系统（当前支持 Linux）」而不是隐藏；顺带把 5s 采样失败静默改为单次提示。
- **验收**：连无 `/proc` 主机时出现边界说明文案（截图）；Linux 靶机监控条回归正常；monitor 单测全过。
- **范围**：dou-app `src-tauri/src/monitor.rs`、`components/TerminalPanel.vue` 监控条空态。

### R8 档案双击一键连接主路径

- **问题**：保险库档案已在连接管理页，但「入库之后怎么用」没有主路径；会话不持久，重启后全靠手填。
- **整改**：连接管理卡片增加主操作：密钥目标「连接」= 解锁校验→`vault_get_key`→`open_pty(key_path)`→开标签；密码目标「连接」= 行内密码框→`open_pty(password)`；双击卡片等价主操作。
- **验收**：① 双击已入库密钥目标 ≤3 秒出现可输入终端（截图/UIA）；② 密码目标同路径可用；③ 失败走 R3 新文案；④ vue-tsc + 单测全过。
- **范围**：dou-app `components/ConnectionsPanel.vue`、`core/useTerminal.ts`（新增 `connectByTarget`）。
