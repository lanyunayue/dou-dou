## 2. 需求来源与用户原始语句

### 2.1 用户原始语句（逐字）

> 「做一下 window 系列的兼容性，至少保障 window 11 能够兼容，同时对软件进行一些风控，防破甲，暴力破解的相关工作，并且进行 W-03 git 化 → W-11 状态模型 → W-15 统一鉴权，全部完成」

用户同时要求**真实代码落地、编译与测试通过**，不是只出文档。本阶段仅负责增量 PRD，架构师 → 工程师 → QA 由主理人依次派发。

### 2.2 本轮三块工作（拆解）

| # | 工作块 | 用户措辞 | 本轮交付形态 | 主承接分节 |
|---|---|---|---|---|
| A | Windows 11 兼容性 | 「window 系列的兼容性，至少保障 window 11 能够兼容」 | 兼容矩阵 + 用户故事 US-W01~07 + 需求 INC-W01~10（网关进程 / 构建脚本 / 配置 / 探测脚本 / CI，不引入新页面） | §4 |

### 2.3 本轮不做（边界声明）

- 不改前端形态：Q4 未拍板，桥接与桌面页面（W-26 / W-28 / W-29 / W-32 等 T04 工单）不在本轮；Windows 兼容只覆盖**网关进程、构建脚本、配置、探测脚本与 CI**（【默认假设】6）。
