# 换机重建指南

> 面向「豆 Dou」桌面客户端项目。解压本包后按本文恢复开发环境。
> 全部命令在 **Windows + PowerShell** 下执行；仓库路径含中文时脚本已做兼容处理。

## 0. 解压后目录结构

```
dou-handover-YYYYMMDD-HHMM.zip
├── MANIFEST.txt              打包清单
├── 新机重建指南.md            本文件
├── verify.sh                 一键验证脚本
├── dou-app/                  桌面客户端（主战场，含 .git）
└── dou-workspace/            网关 + 文档 + 工具（含 .git）
```

建议解压到**纯 ASCII 路径**，例如 `D:\dou-handover\`。
原因：MinGW 工具链的 `dlltool` 按 ANSI 代码页解析路径，中文路径会导致
`Can't create .lib file`。本项目现已固定 MSVC 工具链，不受此影响，
但网关 workspace 仍用 GNU，保持 ASCII 路径更保险。

## 1. 前置依赖

| 依赖 | 版本 | 安装 |
|---|---|---|
| Rust | stable，**MSVC 工具链** | `rustup default stable-x86_64-pc-windows-msvc` |
| Visual Studio | 2022/2026，需 **C++ 生成工具** 工作负载 | VS Installer 勾选「使用 C++ 的桌面开发」 |

| Git | 2.30+ | 官网安装 |

**工具链已被项目锁死**，无需手动选：

- `dou-app/rust-toolchain.toml` → `channel = "stable-x86_64-pc-windows-msvc"`
  （进入该目录跑 cargo 会自动切到 MSVC）
- `dou-workspace/.cargo/config.toml` → 锁 MinGW GNU 的 linker/ar 与
  `target-dir = D:/dou-target`（本机已改好）。**换机后需改这些绝对路径**（见第 3 步）。

> ⚠️ 两个仓库用**不同工具链**，这是有意设计：
> 客户端用 MSVC（Tauri 官方推荐，规避 GNU 的 `export ordinal too large`）；
> 网关沿用 GNU（历史稳定）。请勿混用。

## 1.5 先把 git 历史恢复出来

包内给的是**工作树快照 + `history.bundle`（完整历史）**。如果要继续用 git
（强烈建议，否则失去全部版本历史与 revert 能力），先执行：

```powershell
cd <解压路径>\dou-app
git init
git fetch history.bundle 'refs/*:refs/*'
git checkout -f main        # 必须带 -f
git tag -l                  # 应看到 handover-baseline
git branch -a               # 应看到 4 个分支
git log --oneline           # 应能看到本轮全部提交
```

`dou-workspace` 同样操作一次（只有 `main` 一个分支）。

> ⚠️ **`git checkout -f` 的 `-f` 必须加**：包内已含 `git archive` 导出的工作树文件，
> 不加 `-f` git 会报
> `error: The following untracked working tree files would be overwritten by checkout`
> 而拒绝执行（这是实测踩过的坑）。

想省事也可以直接在工作树上开发、不做 git 操作 —— 但那样就没有版本历史了。

### 首次 `cargo build` 会比较久

依赖已全部锁定在 `Cargo.lock` 里，但**新机需要联网下载 crates 源**。
本机 CARGO_HOME 为 `D:\dev\.cargo`，缓存已联网预热。`verify.sh` 与 `dev.ps1`
会检测缓存：有缓存才加 `--offline`，新机缓存为空时自动走联网，不必手改脚本。

### 3.1 改掉两处绝对路径

**① `.cargo/config.toml`** —— `target-dir` 与 linker/ar 路径指向旧机：

```toml
[build]
target-dir = "D:/dou-target"          # ← 本机已改好；换机改这里

[target.x86_64-pc-windows-gnu]
linker = "D:/w64devkit/bin/x86_64-w64-mingw32-gcc.exe"   # 本机 w64devkit
ar    = "D:/w64devkit/bin/ar.exe"                    # 本机 w64devkit
```

> 新机没装 MinGW 的话，二选一：
> **(a)** 装 MinGW 并改路径：
> `winget install --id BrechtSanders.WinLibs.POSIX.UCRT -e --scope user`
> **(b)** 直接把网关也切到 MSVC：删掉整个 `[target.x86_64-pc-windows-gnu]` 段即可。

**② `scripts/build.ps1`** —— 里面用 `Get-ChildItem` 动态找 MinGW，路径变了会自动适配，
一般无需改。

## 4. 敏感数据：**不在压缩包里，需单独转移**

打包时已按 W-03 红线排除下列文件（防止凭据随包扩散）：

| 文件 | 默认位置 | 说明 |
|---|---|---|
| `token.txt` | `%LOCALAPPDATA%\dou\` | 网关访问令牌 |
| `known_hosts.json` | `%LOCALAPPDATA%\dou\` | 已信任主机密钥（**建议重新学习，不要拷贝**） |
| `vault.json` | `%LOCALAPPDATA%\dou\` | 凭据保险库（加密，但迭代次数已升级） |
| `id_ed25519` 等私钥 | `%LOCALAPPDATA%\dou\keys\` | SSH 私钥 |
| `audit.db` | 运行时 | 审计库 |

转移方式（按需，不要全量拷贝）：

- **只想继续开发** → 什么都不用拷，重新初始化即可。
- **要恢复已配好的靶机** → 单独拷 `token.txt`（用安全渠道），其余重新生成。
- **要恢复保险库** → 拷 `vault.json`（AES-256-GCM 加密），旧文件按 200k 迭代仍能解锁。

> `known_hosts.json` **不建议拷贝**：换机后重新学习主机密钥更安全
> （TOFU 首次连接会重新记录）。

## 7. 遇到问题

| 现象 | 处理 |
|---|---|
| `cargo build` 卡在下载 | 正常首次拉 crates；离线则拷 `%USERPROFILE%\.cargo\registry` |
| `ld.exe: export ordinal too large` | 用错工具链了，确认在 `dou-app` 下（已锁 MSVC） |
| `Can't create .lib file` + 中文路径 | 路径含中文，挪到纯 ASCII 目录 |
| `error deleting lock file ... 拒绝访问` | Windows 增量编译锁残留，无害，删 `target/debug/incremental` 即可 |
| 端口 7419 / 2222 被占 | `netstat -ano | findstr :7419`，结束对应 PID |
| 靶机连不上（os error 10061） | 跑 `tools/start_dou_tunnel.sh`，或用回环靶机 `dev.ps1 ssh-test` |

- 未跑 / 未通过的项目**如实标注**，不粉饰；已复验的必须写明命令与结果。
- 新增两条本机坑：① 无 BOM 的 UTF-8 `.ps1` 在 PowerShell 5.1 下按 GBK 解码，中文注释的乱码字节会破坏脚本块解析（曾让 `env-check.ps1` 的 MSVC 项假 FAIL）→ 新增注释一律 ASCII，或给文件加 UTF-8 BOM；② Git Bash 自带 `/usr/bin/link.exe`（GNU coreutils），MSVC 未被发现时会伪装成链接器报 `extra operand`，别误判成「link.exe 缺失」。
